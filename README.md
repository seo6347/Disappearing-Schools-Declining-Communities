# 학교가 사라진 다음
### Disappearing Schools, Declining Communities

**학교 세 곳을 하나로 합치면, 아이들의 등굣길과 마을의 교육 기반은 어떻게 달라질까요?**

학교 통폐합은 학교 수의 변화이면서, 학생들이 매일 이동해야 하는 거리와 시간의 변화이기도 합니다. 어떤 지역에서는 여러 학교 가운데 하나가 없어지지만, 다른 지역에서는 마을의 마지막 공립초등학교가 사라질 수 있습니다.

이 프로젝트는 교육부가 발표한 '소규모 학교 혁신을 통한 지역 교육력 제고 방안'(2026.06) 속 통폐합 모델을 근거로 전국 소규모 공립초등학교를 대상으로 **세 학교를 한 학교로 통합하는 반사실적 시나리오**를 구성했습니다. 통합학교의 수용력과 도로 접근성을 고려한 뒤, 학생들의 통학부담이 얼마나 달라지고 어느 읍·면에서 마지막 공립초등학교가 사라지는지 살펴봤습니다.

SBS 데이터사이언스&저널리즘 아카데미 5기 최종 프로젝트에서 출발했으며, 공간자료 처리, 학교 통합 후보 구성, 정수최적화를 이용한 비중복 학교 묶음 선정, 학생 가중 통학부담 분석을 연결했습니다.

## 1. 무엇을 알아보려 했나요?

분석은 다음 세 가지 질문에서 출발했습니다.

1. **어떤 학교들을 통합 가능한 후보로 묶을 수 있을까?**  
   가까이 있다는 이유만으로 학교를 합칠 수는 없습니다. 같은 교육지원청에 속하는지, 통합 후 학생들을 수용할 교실이 있는지, 도로로 이동할 수 있는지도 함께 살펴봤습니다.

2. **학생들이 실제로 이동해야 하는 통학시간은 얼마나 달라질까?**  
   학교와 학교 사이의 거리만으로는 학생들의 부담을 알기 어렵습니다. 학생들이 거주한다고 추정한 지점에서 현재 학교와 통합학교까지의 경로를 각각 계산했습니다.

3. **학교 통합이 지역의 교육 기반에 어떤 공백을 만들까?**  
   학교가 줄어드는 지역 가운데, 특히 마지막 공립초등학교 본교가 사라지는 읍·면을 구분했습니다.

이 분석은 실제 통폐합 예정지를 예측하거나 특정 학교의 폐교를 제안하기 위한 것이 아닙니다. **명시한 조건으로 통폐합을 가정했을 때 나타나는 변화를 살펴보는 시뮬레이션**입니다.

## 2. 주요 결과

아래는 **교실당 학생 수를 28명으로 가정하고, 선정된 각 학교 묶음에서 전체 학생의 평균 통학시간 변화가 가장 작은 통합학교를 선택했을 때**의 결과입니다.

| 살펴본 항목 | 시뮬레이션 결과 |
| --- | ---: |
| 선정된 3개교 통합 묶음 | 720개 |
| 시나리오상 통합으로 없어지는 학교 | 1,440개교 |
| 선정된 학교에 다니는 전체 학생 규모 | 약 163,364명 |
| 통합으로 학교를 옮기는 학생 규모 | 약 93,673명 |
| 학교를 옮기고 편도 통학시간도 증가하는 학생 규모 | 약 78,462명 |

**학생 규모는 개별 학생을 직접 추적한 인원수가 아니라, 인구 자료를 학교별 실제 재학생 수에 맞춰 보정한 추정치입니다.** 표에서는 이해를 돕기 위해 반올림했습니다. 통학시간 관련 수치는 경로 분석이 가능한 학생을 기준으로 계산했습니다.

평균 증가 시간 6.0분은 전체 학생의 평균이 아니라, **학교를 옮기면서 통학시간이 증가한 학생들만의 평균**입니다. 시간이 줄어든 학생이나 같은 학교에 계속 다니는 학생까지 포함하면 다른 값이 됩니다.
e.g. 학교를 옮긴 학생들을 대상으로 하면 평균 4.4분이 증가합니다. (학교를 옮기면서 통학시간이 감소한 경우도 존재합니다.) 

또한 ‘440곳’은 이 시나리오에서 마지막 **공립초등학교 본교**가 사라지는 읍·면의 수입니다. 해당 지역의 모든 교육시설이 없어지거나 지역소멸이 발생한다는 뜻은 아닙니다.

## 4. 어떻게 분석했나요?

이 분석은 현재의 학교 배치와, 일정한 규칙으로 세 학교를 하나로 통합한 경우를 비교하는 **반사실적 시뮬레이션**입니다.

학교를 임의로 묶거나 통학시간이 크게 증가하는 사례만 선택하지 않도록, 아래 순서에 따라 대상·후보·수용력·접근성·최종 존치학교를 결정했습니다.

### ① 학생분포를 추정하고 실제 재학생 수에 맞췄습니다

집계구의 5-9세 인구와 10-14세 인구에 각각 3/5를 적용해 초등학령인구를 추정했습니다. 집계구 대표점을 통학구역과 연결하고, 해당 구역에 연결된 공립초등학교에 추정 인구를 배분했습니다.

이후 학교별 배분 합계가 실제 재학생 수와 맞도록 학생 가중치를 보정했습니다. 인구 추정값을 그대로 학생 수로 사용해 분석 대상의 규모가 부풀려지는 것을 방지하고, 학교별 실제 재학생 수를 기준으로 계산하기 위한 처리입니다.

학생 가중치는 분석상 배분값이므로 소수를 유지합니다. 중간 단계에서 학생 수를 반올림해 누적 오차를 만들지 않고, 최종 표에서 필요한 경우에만 표시용으로 반올림합니다.

통학구역에 연결되지 않는 지점이나 보정이 어려운 학교는 상태를 구분해 남깁니다. 초기 인구 추정식과 가중치 보정은 학생들의 실제 거주지를 관측한 결과가 아니라, 확보한 인구·학교 자료를 연결하기 위한 추정 방법입니다.

### *왜 집계구 인구를 사용했나요?*

통학시간을 추정하려면 학생 수뿐 아니라 학생들이 어느 위치에 거주하는지를 알아야 합니다. 시군구별 연령 인구는 나이별 인구 규모를 파악하는 데 유용하지만, 넓은 행정구역 안에서 학생들이 어디에 분포하며 어느 학교로 통학하는지 추정하기에는 공간적 해상도가 부족합니다.

이에 읍면동보다 작고 인구규모, 사회경제적 동질성(주택유형, 자가), 형상을 고려하여 구축한 최소 통계 집계구역인 집계구의 연령별 인구와 초등학교 통학구역을 결합했습니다. 같은 시군구 안에서도 인구가 모여 사는 위치를 구분하고, 통학구역을 기준으로 각 학교에 대응하는 학생 분포를 추정하기 위해서입니다. 이렇게 추정한 분포는 학교별 실제 재학생 수에 맞춰 가중치를 보정했습니다.

관련 코드: [학생분포 추정·보정](scripts/01_estimate_current_student_distribution.py) · [통학구역 미배정 지점 분석](scripts/01-1_analyze_no_zone_sensitivity.py)

### ② 통합 후보가 될 학교의 범위를 정했습니다

후보 학교는 다음 조건을 충족해야 합니다.

- 설립형태가 **공립**인 초등학교
- 전처리된 학교 마스터에서 **작은학교로 분류**된 학교
- 분교가 아닌 **본교**
- 앞 단계의 학생분포 보정 결과가 **정상인 학교**
- 소속 교육지원청과 유효한 위도·경도를 확인할 수 있는 학교

작은학교 여부는 입력 파일의 분류를 사용합니다. 해당 분류를 처음 만드는 전처리 과정은 현재 저장소의 공개 범위 밖에 있습니다.

대상 학교에 교육지원청이나 좌표가 없거나 좌표 범위에 문제가 있으면, 이를 알리지 않고 건너뛰지 않고 실행을 중단해 확인하도록 했습니다.

관련 코드: [후보 학교 모집단 구성](scripts/02-1_analyze_distance_graph_sensitivity.py)

### ③ 같은 교육지원청 안에서 가까운 세 학교를 후보로 만들었습니다

같은 교육지원청에 속한 학교끼리 직선거리를 계산했습니다. 서로 다른 교육지원청의 학교를 하나의 통합 후보로 섞지 않았습니다.

거리 기준에 따른 후보 규모의 변화를 살펴보기 위해 **3·5·10·15·20·30km**를 비교하는 민감도 분석을 수행하며, 최종적으로는 **10km 기준**을 적용하였습니다. 

민감도 분석에서는 기준별 간선 수, 고립학교, 연결된 학교 집단과 3개교 후보 수 등을 비교합니다. 

직선거리 10km 이하인 학교쌍을 연결하고, 세 학교가 이 연결을 통해 하나로 이어지는 조합을 통합 후보로 만듭니다.

예를 들어 A–B와 B–C가 각각 10km 이내이면 A–B–C 후보를 구성할 수 있습니다. 이때 A–C가 반드시 10km 이내인 것은 아닙니다. 직선거리는 후보를 찾는 기준이며, 도로 이동시간은 뒤 단계에서 별도로 확인합니다.

### *왜 거리 기준을 10km로 정했나요?*

거리 기준을 지나치게 좁히면 주변 학교가 드문 농산어촌·인구감소지역의 학교들이 통폐합 후보에서 누락될 수 있습니다. 반대로 기준을 계속 넓히면 새롭게 포함되는 학교에 비해 검토해야 할 조합이 급격히 늘어납니다. 이에 **3·5·10·15·20·30km의 거리 기준을 비교**하고, 학교의 후보 참여 범위와 후보 조합 수의 증가를 함께 살폈습니다.

주요 비교 결과는 다음과 같습니다. 비율의 분모는 분석 대상 학교 **2,503개교**이며, 후보 수는 수용력·도로경로 검토 전의 3개교 조합 수입니다.

| 거리 기준 | 3개교 후보에 참여 가능한 학교 | 대상 학교 대비 비율 | 후보 조합 수 |
| ----- | ----------------: | ----------: | ------: |
| 5km   |           1,517개교 |      60.61% | 17,182개 |
| 10km  |           2,382개교 |      95.17% | 48,273개 |
| 15km  |           2,480개교 |      99.08% | 81,302개 |

5km에서 10km로 넓히면 후보에 참여할 수 있는 학교 비율이 **34.56%p** 증가합니다. 반면 10km에서 15km로 넓힐 때에는 참여 비율이 **3.91%p** 늘어나는 데 그치지만, 후보 조합 수는 약 **68%** 증가합니다. 즉, 10km까지는 후보 참여 범위가 크게 확대되지만, 그 이후에는 추가로 포함되는 학교에 비해 검토해야 할 조합이 빠르게 늘어납니다.

10km는 같은 교육지원청 내 **두 번째로 가까운 학교까지 거리의 90분위 값인 9.925km**와도 가깝습니다. 이러한 비교를 바탕으로, 5km 기준에서 발생하는 지역 누락을 줄이면서 대상 학교의 대부분을 후보에 포함할 수 있는 **10km를 본 분석의 거리 기준으로 선택했습니다.** 이는 민감도 비교를 바탕으로 한 분석상의 선택이며, 모든 지역에 적용되는 유일한 최적 거리를 의미하지는 않습니다.

여기서 10km는 학교 사이를 연결하는 기준입니다. 세 학교가 연결된 후보에는 A–B와 B–C가 각각 10km 이내인 경우도 포함되므로, 후보 안의 모든 학교 쌍이 반드시 10km 이내인 것은 아닙니다. 이후 별도의 도로경로 검토를 통해 실제 이동 가능성을 확인합니다.

### ④ 세 학교의 학생을 실제로 수용할 수 있는지 확인했습니다

A–B–C 후보가 있다면 다음과 같이 최대 세 가지 존치학교안을 검토합니다.

| 존치학교안 | 통합 후 남는 학교 | 통합으로 없어지는 학교 |
| --- | --- | --- |
| A로 통합 | A | B·C |
| B로 통합 | B | A·C |
| C로 통합 | C | A·B |

각 존치학교안에 대해 다음 조건을 확인합니다.

**존치학교의 일반교실 수 × 교실당 학생 수 ≥ 세 학교의 실제 재학생 수 합계**

현재 대표 시나리오인 **CAP28은 교실당 28명**을 가정합니다. 세 학교의 교실을 합산하는 것이 아니라, 남게 될 한 학교의 일반교실만으로 통합 학생 전체를 수용할 수 있는지 평가합니다.

28명은 과밀학급 기준을 참고해 설정한 **시뮬레이션의 수용력 상한 가정**입니다. 교육부의 [교육회복 종합방안 발표](https://www.korea.kr/briefing/policyBriefingView.do?newsId=156464003)에서도 학급당 학생 수 28명 이상인 과밀학급을 해소 대상으로 제시했습니다.

다만 이 계산은 학년별 학급 편성, 특별실의 전환 가능성, 교원 배치 등을 모두 반영한 실제 학교 운영계획은 아닙니다. 정확히 28명인 경우도 계산상 허용하므로, CAP28을 통과했다는 사실이 과밀학급이 발생하지 않음을 보장하지는 않습니다.

초기에는 교실당 19명인 CAP19도 비교합니다. 이후 대표 통학부담·학교 공백 분석은 CAP28을 사용합니다. CAP28은 CAP19보다 수용 가능한 학생 수를 크게 잡는 가정이므로, 더 많은 통합안이 가능해질 수 있습니다.

관련 코드: [학교 수용력 평가](scripts/03-1_evaluate_capacity_scenarios.py)

### ⑤ 도로 접근성이 극단적으로 나쁜 존치학교안을 제외했습니다

수용력 조건을 통과한 안에 학교 간 도로경로를 연결했습니다. A를 존치한다면 B→A와 C→A처럼, 폐교 후보 학교에서 존치학교로 이동하는 두 방향별 경로를 확인합니다.

각 안에서 두 경로의 **최대 이동시간**과 **최대 우회비율**을 각각 계산합니다. 우회비율은 실제 도로거리를 직선거리로 나눈 값입니다.

아래 조건 중 하나라도 해당하면 그 존치학교안을 제외합니다.

| 제외 조건 | 적용 방식 |
| --- | --- |
| 페리 이용 필요 | 두 경로 중 하나라도 페리가 필요한 경우 |
| 극단적인 이동시간 | 두 경로의 최대 이동시간이 **80분 초과**인 경우 |
| 긴 이동시간과 큰 우회가 함께 존재 | 최대 이동시간이 **40분 초과**이면서 최대 우회비율이 **3배 초과**인 경우 |

이동시간과 우회비율의 최대값은 두 경로에서 각각 구합니다. 두 최대값이 반드시 같은 경로에서 나오는 것은 아닙니다.

우회비율이 3배를 넘는다는 이유만으로 제외하지는 않습니다. 정확히 40분·80분·3배인 경우도 해당 ‘초과’ 조건만으로는 제외하지 않습니다. 이 기준을 적용하기 전에는 여러 시간·우회 기준에 따른 민감도 결과를 비교하도록 구성했습니다.

제외는 세 학교 묶음 전체가 아니라 **개별 존치학교안**에 적용합니다. A로 통합하는 안이 탈락해도 B 또는 C로 통합하는 적격안이 남으면 해당 후보는 유지합니다. 탈락안과 사유도 상세표에 남깁니다.

이 단계의 학교 간 시간은 극단적인 접근성의 후보를 거르는 지표입니다. 학생들의 최종 통학시간은 집계구 대표점에서 학교까지의 별도 경로로 계산합니다.

관련 코드: [도로 접근성 민감도 분석](scripts/03-3_analyze_road_access_sensitivity.py) · [최종 도로 접근성 규칙](scripts/03-4_finalize_road_access_options.py)

### ⑥ 학교가 중복되지 않는 통합 묶음을 선정했습니다

한 학교가 A–B–C와 A–D–E에 동시에 포함될 수는 없습니다. 따라서 적격 후보 중 학교가 겹치지 않는 조합을 교육지원청별로 선정합니다.

선정 기준은 다음 순서로 적용합니다.

1. **선택하는 3개교 묶음 수 최대화**  
   학교는 최대 한 묶음에만 포함될 수 있습니다. 모든 묶음이 세 학교로 구성되므로, 묶음 수 최대화는 포함 학교 수 최대화와 같습니다.

2. **같은 최대 묶음 수에서 학교 간 접근시간 점수 합계 최소화**  
   각 후보의 적격 존치학교안 가운데 ‘두 학교에서 존치학교까지 걸리는 시간의 최댓값’이 가장 작은 값을 후보 점수로 사용합니다. 선택된 후보들의 점수 합계가 작은 조합을 우선합니다. 최적화에는 이 값을 초 단위 정수로 반올림해 사용합니다.

3. **앞의 두 기준도 같으면 후보 ID 정렬 순위합 최소화**  
   추가 동률 처리 기준을 두어 후보 선택 규칙을 명시했습니다.

**이 단계에서 결정하는 것은 A–B–C라는 묶음입니다. A·B·C 중 어느 학교를 남길지는 아직 확정하지 않습니다.** 선정된 묶음의 적격 존치학교안을 다음 단계로 모두 넘깁니다.

기준 묶음은 CAP28에서 선정합니다. CAP19 비교에서는 같은 묶음의 유지 가능성을 평가하며, CAP19에 맞춰 다른 학교 묶음으로 바꾸어 재최적화하지 않습니다.

관련 코드: [비중복 군집 선정](scripts/03-5_select_nonoverlapping_clusters.py)

### ⑦ 학생의 통합 전후 경로를 계산한 뒤 존치학교를 선택했습니다

선정된 학교에 배정된 집계구 대표점마다 다음 두 경로를 연결합니다.

- **통합 전:** 대표점 → 현재 학교
- **통합 후:** 같은 대표점 → 각 존치학교안의 학교

네이버 지도 API로 당시 수집한 도로경로 자료를 사용해 시간과 거리의 차이를 계산하고, 해당 지점의 학생 가중치를 반영합니다. 공개 코드의 기본 실행은 저장된 경로 자료를 사용하므로 API를 다시 호출하지 않습니다.

통학시간 변화는 **통합 후 시간 − 통합 전 시간**입니다. 

각 묶음의 적격 존치학교안에 대해 다음 두 결과를 모두 산출합니다.

| 선택 기준 | 의미 |
| --- | --- |
| **하한안 — `LOWER_BOUND`** | 학생 가중평균 통학시간 변화가 가장 작은 존치학교안 |
| **상한안 — `UPPER_BOUND`** | 학생 가중평균 통학시간 변화가 가장 큰 존치학교안 |

전체 학생을 기준으로 선택하는 경우와 학교를 옮기는 학생만 기준으로 선택하는 경우를 각각 계산합니다. 평균값이 같으면 상위 10% 기준 변화량, 최대 변화량, 학교 ID를 차례로 사용해 선택 순서를 정합니다.

**최종 결과는 하한안을 선택함으로써, 통학시간의 변화가 과대추정되지 않도록 하였습니다.** 

관련 코드: [통합 전후 통학부담 계산](scripts/04-4_calculate_commute_time_changes.py) · [하한·상한 존치학교안 선택](scripts/04-5_select_commute_bounds.py)

### ⑧ 하한안을 적용해 학교 공백과 지역별 부담을 살펴봤습니다

전체 학생 기준 하한안을 적용한 뒤, 읍·면별 공립초등학교 본교 수가 통합 전후 어떻게 달라지는지 계산했습니다. 마지막 학교가 사라지는 읍·면과 그 지역에 배분된 학생 규모를 구분했습니다.

따라서 **440곳은 통학시간 변화가 작은 존치학교안을 선택한 시나리오의 결과**입니다. 

학교를 옮기고 통학시간이 증가한 학생들의 분포도 별도로 분석합니다. 이 집단의 평균 증가 시간과 전체 학생 또는 전체 이동 학생의 평균은 구분해서 읽어야 합니다.

관련 코드: [학교 공백 분석](scripts/05_analyze_school_voids.py) · [통학부담 분포](scripts/06_analyze_commute_increase_distributions.py) · [지역별 비교](scripts/07_analyze_regional_commute_burden.py)

### 분석 기준 요약 

현재 결과에는 분석 결과를 유리하게 산출하지 않기 위하여 다음과 같이 통학부담을 작게 산정하는 방향의 가정이 포함되어 있습니다.

- 학생의 출발점에서 학교까지 곧바로 가는 자동차 경로를 사용하며, 통학버스의 우회·승하차·대기시간을 더하지 않습니다.
- 최종 결과는 남은 통합학교안 가운데 전체 학생의 평균 통학시간 변화가 가장 작은 하한안을 사용합니다.
- 존치학교 선택에 쓰는 평균에는 통학시간이 줄어든 학생의 감소분도 포함합니다.
- 통폐합 대상 학교 군집 선정에는 같은 교육지원청 내이면서 직선거리가 10km 이하인 학교만 포함됩니다.
- 중복되지 않게 군집을 선정하는 과정에서 학교 수준의 도로 접근성이 더 좋은 경우만 선택하였습니다.
- 학교간 도로시간 검증 과정에서 이동 경로에 해상교통수단이 포함되거나, 최대 이동시간이 40분을 넘으면서 직선거리 대비 실제 이동거리가 3배 이상 차이나거나, 학교 간 이동시간이 80분을 초과하는 극단 경로는 제외하였습니다. 

## 5. 결과를 읽을 때 주의할 점

### 실제 통학버스 운행시간을 계산한 것은 아닙니다

도로경로는 대표점에서 학교까지 곧바로 이동하는 자동차 경로입니다. 여러 학생을 태우기 위한 우회, 승하차, 대기시간은 포함하지 않습니다.

사용한 경로에는 당시 일요일 새벽의 교통상황이 반영되어 있습니다. 실제 평일 등교시간이나 통학버스 운행시간과 같다고 볼 수 없습니다.

### 실제 통폐합 결정에 필요한 모든 조건을 담지는 못했습니다

교실 수와 접근성 외에도 교육과정, 시설 상태, 통폐합 대상 학교들의 교감 등 이해관계, 주민과 학생의 의견, 지역의 생활 여건 등 다양한 조건이 실제 결정에 영향을 줄 수 있습니다. 이 시뮬레이션의 적격 판정은 분석에서 설정한 조건을 통과했다는 의미입니다.

### 학교 소멸과 지역소멸의 인과관계를 입증한 결과는 아닙니다

이 분석이 보여주는 것은 가정한 통폐합 이후의 통학부담과 학교 배치 변화입니다. 이후 인구 유출이나 지역소멸이 실제로 발생하는지는 별도의 자료와 취재가 필요한 질문입니다.

## 6. 직접 같은 분석을 실행하려면

실제 분석에서는 API 호출 등이 사용되었으나, 재현성을 위하여 미리 준비된 데이터를 사용하므로 **API 키 발급이나 별도의 경로 수집은 필요하지 않습니다.**

### 준비물

- Python 3.12
- 내려받은 저장소 코드
- 아래 링크의 `data.zip`
- 명령어를 입력할 터미널. VS Code를 사용해도 됩니다.

### 1) 코드와 데이터 내려받기

이 저장소 상단의 **Code → Download ZIP**을 눌러 코드를 내려받고 압축을 해제합니다.

이어서 [분석 데이터 `data.zip`](https://drive.google.com/file/d/1HgFXBW5J9d3-zDmiuqZ7gLOriOFdx4Df/view?usp=sharing)을 내려받습니다. 데이터 압축은 **`run_pipeline.py`가 있는 폴더에** 해제합니다.

| 항목 | 올바른 위치 |
| --- | --- |
| 전체 실행 파일 | `run_pipeline.py` |
| 패키지 목록 | `requirements.txt` |
| 분석 코드 폴더 | `scripts/` |
| 학교 정보 파일 | `data/01_raw/elementary_master.csv` |
| 공간자료 | `data/01_raw/` 안의 GPKG 2개 |
| 학교 간 경로 | `data/01_raw/api_routes/school_road_routes.csv` |
| 학생 통학경로 | `data/01_raw/team_route_results/` 안의 배치별 CSV |

### 2) VS Code에서 프로젝트 열기

VS Code의 **파일 → 폴더 열기**에서 `run_pipeline.py`가 있는 폴더를 선택합니다.

이후 **터미널 → 새 터미널**을 선택합니다. 아래 명령은 모두 이 프로젝트 폴더에서 실행합니다.

### 3) 실행 환경 준비하기 — Windows

PowerShell 터미널에서 아래 명령을 한 줄씩 실행합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

첫 번째 명령은 이 프로젝트에서 사용할 Python 환경을 만듭니다. 두 번째 명령은 분석에 필요한 패키지를 설치합니다.

### 4) 전체 분석 실행하기 — Windows

패키지 설치가 끝나면 다음 명령을 실행합니다.

```powershell
.\.venv\Scripts\python.exe run_pipeline.py
```

분석은 다섯 단계로 진행됩니다. 마지막에 `[DONE]`이 표시되면 요청한 단계가 완료된 것입니다.

각 실행 단계의 상세 기록은 `logs/`에 저장됩니다. 화면에 새로운 메시지가 바로 나타나지 않더라도 해당 작업의 로그에 진행 내용이 기록될 수 있습니다.

<details>
<summary>macOS·Linux 실행 방법</summary>

Python 3.12가 설치된 상태에서 프로젝트 폴더의 터미널에 입력합니다.

```bash
python3.12 -m venv .venv
```

### 다시 실행하거나 일부 단계만 실행하기

이미 생성한 최종 결과를 덮어쓰며 다시 실행하려면 다음 명령을 사용합니다.

```powershell
.\.venv\Scripts\python.exe run_pipeline.py --overwrite
```

일부 단계만 실행할 수도 있습니다. 예를 들어 앞선 단계의 결과가 있는 상태에서 마지막 분석 단계만 다시 실행하려면 다음과 같이 입력합니다.

```powershell
.\.venv\Scripts\python.exe run_pipeline.py --stage 5 --overwrite
```

| 실행 단계 | 수행하는 작업 |
| --- | --- |
| 1 | 학생분포 추정과 통학구역 미배정 지점 분석 |
| 2 | 거리 기준 비교와 3개교 후보 생성 |
| 3 | 수용력·도로 접근성 평가와 통합 묶음 선정 |
| 4 | 통합 전후 통학부담 계산과 하한·상한 선택 |
| 5 | 학교 공백, 통학부담 분포, 지역별 비교 |

개별 단계는 앞 단계에서 생성한 파일을 사용합니다. 처음 실행할 때는 전체 실행 명령을 사용하는 것이 좋습니다.

## 8. API 수집 코드와 공개 범위

기본 실행은 **당시 수집을 완료한 도로경로 파일을 읽어 계산**합니다. 실시간 교통을 반영하는 경로를 새로 조회하면 같은 출발지와 도착지라도 시간이 달라질 수 있기 때문입니다.

수집 방법을 확인할 수 있도록 API 관련 코드는 남겨두었습니다.

- `03-2_fetch_school_road_routes.py`: 기본 실행에서는 저장된 학교 간 경로를 연결합니다. 실제 API 호출은 별도로 `--execute`를 지정했을 때만 수행합니다.
- `04-2_collect_naver_commute_routes_colab.ipynb`: 팀별 경로 수집에 사용한 선택 도구입니다. 기본 분석에서는 실행하지 않으며, 수집 실행도 기본적으로 비활성화되어 있습니다.

`.env.example`은 API 재수집이 필요한 경우 참고할 수 있는 환경변수 예시입니다. **일반적인 분석 실행에는 `.env`를 만들거나 실제 API 키를 입력할 필요가 없습니다.**

이 저장소는 분석 계산과 결과 생성에 필요한 코드를 중심으로 구성했습니다. 기사 화면, 발표자료, 웹페이지를 제작하기 위한 별도 편집 코드는 포함하지 않습니다.

공개된 입력 자료와 API에서 얻은 정보에는 원자료별 이용 조건이 적용될 수 있습니다. 이 저장소의 공개 자체가 제3자 자료에 대한 별도 이용 허락을 의미하지는 않습니다.
